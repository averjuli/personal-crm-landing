# Лендинг «Личная CRM»

Одна статичная страница: https://vupsen.space. Все кнопки «Добавить первый контакт» ведут в приложение: https://app.vupsen.space

## Команды

```
pnpm install    # поставить зависимости
pnpm dev        # страница с автообновлением: http://localhost:4321
pnpm build      # собрать готовый сайт в папку dist/
pnpm preview    # открыть собранный сайт из dist/
```

## Что где лежит

- `src/data/content.ts` — все тексты страницы и адрес приложения
- `src/styles/tokens.css` — цвета, шрифты, размеры текста, отступы, скругления
- `src/components/` — блоки страницы: шапка, первый экран, проблема, решение, выгоды, финальный призыв
- `desing/` — макет: образцы в HTML, тексты и спецификация
- `.github/workflows/deploy.yml` — выкатка на сервер
- `deploy/nginx/vupsen.conf` — конфиг nginx с заголовками безопасности лендинга, для истории и ручного применения

## Выкатка

Каждый push в `main` сам выкатывает сайт: GitHub Actions собирает `dist/`, копирует его на сервер и проверяет, что https://vupsen.space отдаёт новую версию. Ход выкатки — на вкладке Actions репозитория, там же кнопка «Run workflow», чтобы выкатить заново без изменений.

Настройки в GitHub (Settings → Secrets and variables → Actions):

- секрет `DEPLOY_SSH_KEY` — ключ, которым Actions заходит на сервер
- переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` — адрес сервера, пользователь и отпечаток сервера

На сервере ключ пускает только пользователя `landing-deploy` и только копировать файлы в папку `/var/www/vupsen.space`, которую отдаёт nginx.

## Заголовки безопасности nginx

Конфиг `deploy/nginx/vupsen.conf` соответствует файлу `/etc/nginx/sites-available/vupsen.conf` на сервере. Этот файл общий с приложением: его HTTP-блок и HTTPS-блок приложения сохранены, для лендинга выделен свой HTTP-блок. Другие сайты и общие настройки nginx не меняются. HTML, стили и скрипты лендинга не меняются.

Для HTTPS лендинга заданы HSTS на год только для текущего домена, CSP без nonce с разрешёнными встроенными скриптами и стилями, запрет встраивания через `frame-ancestors 'none'` и `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff` и `Permissions-Policy`, отключающая камеру, микрофон, геолокацию, платежи и USB. Для шрифтов разрешены свой домен и `data:`, поскольку Astro встраивает небольшие подмножества шрифтов прямо в CSS. Заголовки добавляются и к ответам с ошибками. `server_tokens off` скрывает версию nginx в HTTP- и HTTPS-ответах лендинга; имя `nginx` остаётся.

Автоматическая выкатка страницы не устанавливает конфиг nginx. Для первого применения выполните из папки репозитория:

```powershell
ssh crm "mkdir -p ~/landing-security-headers"
scp deploy/nginx/vupsen.conf deploy/nginx/apply.sh crm:landing-security-headers/
ssh -t crm "sudo bash ~/landing-security-headers/apply.sh"
```

Пароль sudo вводится только в вашем терминале. Скрипт рассчитан на исходный конфиг и первую версию заголовков, прочитанные 16 ноября 2026 года: проверяет контрольную сумму, останавливается при чужих изменениях, сохраняет резервную копию, проверяет синтаксис через `nginx -t` и применяет конфиг через reload. При ошибке проверки или reload возвращает прежний файл. Для последующих изменений нужна новая проверка актуального конфига. Скрипт первоначальной настройки сервера `server-setup.sh` может перезаписать этот общий файл; после его запуска нужно сверить настройки с репозиторием.

После применения откройте https://vupsen.space, проверьте все разделы и кнопки страницы на компьютере и телефоне. В инструментах разработчика, на вкладке Network, проверьте заголовки главного документа, шрифтов, favicon и ответа 404. На вкладке Console не должно быть ошибок CSP. HTTP должен перенаправлять на HTTPS без версии nginx. В лендинге одна страница; все три кнопки ведут в приложение https://app.vupsen.space.
